# Optimize Implementation Plan

> 主 agent 在 main 使用 executing-plans 实施，只有独立 review 可委派。

**Goal:** 通过同一个 CLI check 完成优化任务登记、测量、复验和证据回查。
**Architecture:** 独立 flow 使用现有 config、round、process 端口；案例与行为标准归消费仓。
**Tech stack:** strict TypeScript、Node 22、Action-Driver Vitest、项目原生场景。
**Spec:** [设计和调研](../specs/2026-11-01-optimize-design.md)

1. [x] 使用 tests/optimize.test.mjs 从实际 bin 建立临时项目，覆盖 init、配置、采样、比较、失败与非法基线。先观察缺少命令的失败。
2. [x] packages/config 增加独立任务表；apps/optimize 负责运行、证据和对照；apps/cli 接线并复用 packages/runtime 的轮次和安全写入。保持旧项目配置兼容。
3. [x] 在 Action-Driver config/architecture-kit 中登记任务，为 runtime-storage 增加固定输入的测量 fixture。先在未修改产品实现时跑真实 check。
4. [x] 单独修正超过缓存预算后的分页开销，保留序号、水位、事件次序和 limit 语义。在同 run 用 --from 复验，运行项目原有等价性与热路径验证。
5. [x] 检查报告、原始证据与作用范围，运行 Kit build/typecheck/test、Semgrep。所有性能结论限定于实际负载；无法运行的环境任务列明。
