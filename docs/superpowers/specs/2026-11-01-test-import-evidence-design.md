# 测试导入证据

Action-Driver 的测试会把源码作为 esbuild 输入、临时模块内容和断言样例。对测试文件检查缺失导入时，仅从 TypeScript 语法树提取静态导入、重导出、类型引用及带字面量的动态导入和 require 调用。保留真实缺失模块的诊断和原有报告结构。相对类型引用还须识别有效的包类型入口。

## 消费者和整文件证据

独立 mobile 工程的具名导入和重导出按包入口、符号匹配，只计为消费者。Codex command hook 的脚本引用只保留路径。Knip 6 的嵌套文件观测与旧版整文件观测都以文件为目标，default 单独作为 L1 的 Knip 来源，production 独有观测保留为 L2。缺少来源模式的旧 ledger 需重新检查，删除预览仍独立要求 L1 可达性证据。

Knip 的类型和导出证据沿用 mode 字段。两种模式命中时在同一候选保留两个来源；仅 production 命中时，任务提示核对测试和动态消费者。缺失历史来源时不推断模式。
